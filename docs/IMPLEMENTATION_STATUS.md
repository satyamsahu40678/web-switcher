Updated 31 October 2026 (Asia/Kolkata). This file supersedes historical prototype statements only where fresh evidence is recorded below. The original [complete plan](WEB_SWITCHER_PLAN.md), [prototype status](PROTOTYPE_STATUS.md), and prototype ADR remain preserved historical documents.

## Mapped page paths and ordinary navigation — 31 October 2026

Extension development version **0.2.2** makes new manual mappings default to **Keep its page path** and adds **Keep page paths** / **Open homepage only** actions to existing mappings. Existing choices are not silently changed. Changing link behavior replaces the current DNR generation without renewing the mapping's expiry or altering its destination. Compatible public slugs such as `/download-invincible-hindi-dubbed-series/` now remain intact in an explicitly path-preserving mapping; query and fragment data are removed, and sensitive/ambiguous URLs still require review. This cannot establish that a page exists at a third-party destination.

The loop guard consumes browser-owned `webNavigation` transition metadata bound to the exact packaged gate document. Fresh ordinary navigations can proceed without the previous false pause, while client-redirect returns retain the guard. A separate ceiling of six accepted switches per 15 seconds per tab/mapping or signed family bounds ambiguous programmatic link bursts. Missing, unknown or stale metadata retains the conservative guard. The one-time recovery action now preserves the recomputed safe mapped page for a preserve mapping, while homepage and sensitive-link policies remain homepage-only. Rapid switches use unique nonfuture receipt timestamps so valid recent activity/undo references are not immediately pruned.

Local validation: **302 Node/JavaScript tests passed**, zero failures/skips, including nine navigation-metadata tests, worker-level ordinary typed/link visits, one-time document consumption and late-event refusal, burst limits, deterministic same-millisecond activity retention, settings-generation invalidation, preserved expiry/identity, and existing signed-family/permission/expiry checks. Manifest/syntax/package inspection passed for `web-switcher-0.2.2.zip`. Native Chromium regressions cover repeated public article paths, real anchor clicks, destination reload, HTTP/JavaScript return loops, mapping-mode changes and path-preserving recovery; exact-source execution belongs to the fix PR's hosted checks.

`webNavigation` is an additional declared permission. The code ignores unrelated commits and retains no general browsing-history log; the short-lived gate records contain only document identity/classification and time. Pending recovery and undo references can hold the chosen destination URL in session storage for up to two minutes; persistent activity remains origin-only. See the updated [privacy disclosure](privacy.html) and [installation/Store guide](CHROME_INSTALL_AND_STORE.md). The cloud's provider-host policy is now enforced, but no public-domain ownership, actual destination page compatibility or live-provider effectiveness is asserted by these controlled tests.

## Loop-gate recovery — 30 October 2026

Extension development version **0.2.1** adds explicit recovery from the conservative 15-second per-tab mapping/family guard. That guard can pause a deliberate second visit as well as an actual destination bounce. The screen now explains both possibilities, shows the current saved homepage and offers **Open destination homepage once**. A short-lived, single-use authorization binds the exact gate document, tab, source, mapping/family and homepage. Clicking recomputes current policy and permissions, consumes the authorization and renews automatic loop protection; it never forwards the old path, query or fragment. No new browser permission is added.

All **287 Node/JavaScript tests passed locally**, with zero failures/skips, including concurrent/replayed/forged recovery actions, tab/document separation, expiry, permission and policy invalidation, and signed sibling aliases. Manifest/syntax/package checks passed; packaging now uses the manifest version in the ZIP filename. Three native Chromium regression groups cover the reported deep-link shape with a homepage mapping, a real controlled HTTP redirect back into a different old path, and policy changes while the gate is open. The browser workflow runs these alongside existing suites; consult the fix PR's checks for exact-source hosted evidence. See [installation and troubleshooting](CHROME_INSTALL_AND_STORE.md) for updating an existing unpacked installation. The reported public domains' current behavior has not been verified.

## Automatic continuity update

The primary extension flow now accepts only an old HTTPS address. It follows explicitly observed HTTP redirects, Refresh headers, inert meta refresh and `rel=web-switcher-successor` declarations, including an advertised same-origin well-known JSON pointer. It retains an origin-only successor graph for seven days, checks the terminal again before opening, and can skip disappeared intermediate domains using valid remembered links. Source-only following routes future visits through a fresh check; manual mappings remain optional advanced settings. See [automatic continuity](AUTOMATIC_CONTINUITY.md) for the algorithm, demonstration, failure cases and limits.

Declarations establish observed continuity, not ownership or safety. Unknown successors are not guessed. Conflicts, loops, expired history, access denials and TLS errors stop routing. Signed aliases retain a public trust barrier after expiry/revocation/removal, including when reached as an intermediate chain hop, so they cannot silently downgrade to source-declared continuity. Correlated response headers are awaited independently of the fetch promise to handle actual Chromium event ordering. Private URL parts never cross to the discovered domain.

Previous continuity baseline: **152 JavaScript tests passed** (zero failures/skips), including 21 graph tests, 15 transport tests, 30 controller tests and 21 background tests. Six mocked-browser UI contract checks also passed. **83 fetcher Java tests passed** (65 existing plus 18 continuation cases). Manifest/syntax/package checks passed. Native automatic-flow acceptance passed for source `76585a0a4d08d5eb0bcbf403ed9e7335771aac6e` in both push and PR platform runs: all 18 automatic-continuity groups, six native transport checks, six mocked-browser UI contract checks and 19 legacy extension groups. The tests use controlled loopback fixtures and pregranted fixture permissions, not public-site ownership verification or native permission-dialog acceptance.

## Delivery sequence

The release workflow is implemented, with protected-main/tag and exact-SHA green-CI gates, digest-pinned image manifests, SBOM/provenance generation, verification of the published candidate images, and an approval-protected staging deployment with strict SSH host-key verification, HTTPS/no-demo/readiness checks and prior-image rollback. It has not published release images or deployed a public host. Follow [the deployment guide](DEPLOYMENT.md) after supplying the required host, owned domain, OIDC identities, private publisher gateway and securely provisioned keys/secrets. Broader automatic discovery, owner enrollment/recovery and research evaluation are still roadmap items.
