Web Switcher extension privacy policy

Updated 31 October 2026. This policy describes the default browser-side continuity extension distributed from satyamsahu40678/web-switcher. It covers direct continuity checks, followed-site memory, explicitly requested public-source discovery, optional manual overrides and shared destination following, and the client side of an optional configured discovery service. Independently operated services must publish their own recipients, retention and contact policies; this page does not substitute for those policies, the separate web application or a modified extension.

What the extension processes

You enter an old website address or invoke the popup on the current tab. The extension can investigate explicit HTTP/page-declared move signals without asking you to enter a new destination. Initial page paths, queries and fragments are discarded before the root probe. Selected response headers and bounded page content are parsed in memory without executing remote scripts. Supported move signals and valid remembered origin links form an observed successor chain; familiar names, logos and ordinary links are not identity proof.

If you explicitly choose to follow a source, eligible later top-level GET visits pass through a packaged local gate that checks its current chain. Cross-domain following opens a discovered homepage without transferring the original query or fragment; sensitive/ambiguous links can require confirmation. If a source is reachable and has no established move, the gate can resume the original same-origin URL without switching domains. Manual overrides remain a separate user choice. New manual mappings default to preserving compatible public page paths on the selected destination domain; existing saved choices remain unchanged until you select Keep page paths or Open homepage only. Query and fragment data are removed, and sensitive/ambiguous links retain homepage-only confirmation. The destination must still serve the same public path.

Invoking the popup permits inspection of the current tab's origin. Web Switcher does not require the browser's history API or cookies permissions. Version 0.2.2 introduced webNavigation, which can cause Chrome to show a browsing-history permission warning. Version 0.3.0 adds no further declared permission. The extension handles browser-owned transition metadata only for its own top-level packaged gate commits, to distinguish ordinary new visits from redirect returns. Unrelated navigations are ignored, not stored as a browsing history or uploaded. The limited session classification is bound to the gate document, consumed once and valid for at most two minutes; it does not contain remote page paths or the original source envelope.

Optional shared destination following

If you explicitly enable Follow destination moves, all local mappings currently pointing at the same destination join a local shared group. The new-mapping checkbox Follow future moves for all mappings to this destination is off by default. A visit to an enabled group alias, or Check shared destination now, checks that group's current destination root and its supported declared successors. Group discovery does not request each retired alias or send its original page path/query/fragment to the probe. Contacted current/successor websites can see normal connection metadata such as your IP address and timing.

A supported checked move can update every group alias to the same new destination and retain the former current origin as another old alias. Local mappings store a shared seed origin (followOrigin) and the current destination. Learned move evidence uses the existing bounded origin-only continuity graph. Each alias keeps its own enabled state, expiry and homepage/page-path choice; automatic updates never renew expired consent or establish website ownership. Compatible permitted page paths are applied only when navigation opens the current destination, not as a root discovery query.

This is on-visit or explicitly requested checking while the browser is running, not periodic background polling. New-origin permission can be required. The separate, unchecked Allow future destination checks across HTTPS websites choice requests the existing optional HTTPS-wide grant at a save/enable gesture; otherwise each newly reached origin needs its own approval. Broad access does not enroll every website. Missing evidence, conflicts, cycles, signed-history reservations, changed settings or revoked access can leave the group unresolved. Stop following destination moves stops updates for the whole local group while retaining its latest saved mappings. Delete all local data removes those mappings and membership. Exports include the local follow seed with manual mappings, so review imported shared-follow choices and protect the exported file; browser grants and learned graph history are not restored by that export.

Public-source investigation

Search public sources is a separate explicit action for a selected old address. It can investigate historical public evidence even on a first installation without local migration history or a user-supplied replacement. The default keyless mode contacts Archive.org and Internet Archive Web Archive for bounded availability/index records and selected archived captures. These providers receive the normalized selected hostname/root-address query, your IP address and request timing, and apply their own policies. Provider API requests contain constrained query parameters derived from that public root; they do not contain the original browser page's path, query, fragment, cookies or credentials.

Historical redirect/metadata/announcement evidence can suggest candidates. A historical capture, search position, matching name or copied page does not establish current identity or safe content. Candidates remain unverified. Checking a candidate requires its browser origin permission and can follow supported further declarations; opening requires an explicit choice and a fresh check. The top candidate is never silently opened or imported as an observed migration edge. If you explicitly remember a candidate selection, it is an expiring user-configured homepage mapping rather than owner or registry verification. A later explicit Keep page paths change on that saved mapping does not verify the relationship or renew its expiry.

Broader search can use an optional HTTPS discovery service that you configure. That service receives the selected hostname and normal connection metadata. Depending on its configured sources, its provider adapters may send hostname-based queries to Brave Search and public archives; search providers see the service adapter's connection metadata. Service-side candidate probes expose that service's egress address to the checked websites. Before using a service, review its actual endpoint, providers, access rules, retention and operator policy. No commercial search key is embedded in the extension. An individual access token is sent only to its configured service as authorization, not to candidate sites or archive providers.

No unrelated browsing history, followed-site list, manual mapping list or complete local graph is uploaded for a public-source lookup. Provider failures, missing captures and unsupported relationships can leave a source unresolved. Online investigation does not bypass current signed-history reservations or convert unsigned suggestions into signed routing authority.

Local storage and retention

Followed source origins, enabled/paused settings, manual mappings and optional shared-follow seed/current origins, preferences and validation state are stored in your browser profile. Remembered successor edges contain source/destination origins, evidence type and observation/expiry timestamps, not original page paths, queries or response bodies. The current limits are 50 followed sources and 250 edges. An edge is valid for at most seven days after its latest observation; expired edges are pruned on graph reads and periodic maintenance and cannot authorize a remembered fallback. A followed-source subscription persists until you pause, forget or clear it.

Up to ten public-source lookup jobs may be stored locally for at most one hour, including selected source origins, bounded candidate origins, public evidence locators/facts, progress, reason codes and expiry times. Fetched response bodies and the original entered private URL parts are not retained as job content. Expired jobs are pruned when read/maintained; a closed browser cannot perform cleanup until it runs again. A browser-worker restart can interrupt an archive job and mark it interrupted rather than silently repeat external work. Optional service jobs can resume status checks through their existing opaque references.

The configured discovery-service origin is a local setting. Its individual access token is kept in browser session storage, is not returned in settings readback, and is not included in settings exports. Changing the service origin removes its previous session token. Treat tokens as credentials; avoid shared browser profiles and remove them when no longer needed.

Recent routing activity records origin pairs and timestamps rather than original page URLs. Activity uses a 24-hour retention window and is pruned during extension maintenance. If the browser is closed, cleanup resumes when it runs again. Manual mapping expiry stops its routing but does not necessarily delete the saved mapping. Browser/device backups are governed by their own settings.

Separate temporary browser-session state supports redirect-loop protection, one-time recovery and Undo. Gate navigation records retain only document identifiers, packaged gate paths, times and a fresh-navigation classification. Per-tab fixed-mapping, local shared-group and signed-family attempt counters use a 15-second guard window; these local and signed identities remain separate. Recovery and Undo references can retain the exact selected destination URL, including a permitted public page path, with a validity of at most two minutes; they do not retain the original query/fragment or a general browsing history and are not included in settings exports. Expired references cannot authorize a navigation and are pruned during later handling or tab cleanup; session storage ends with the browser session. A recovery click rechecks the current policy and exact target, and does not disable automatic redirect-loop protection.

You can clear recent activity, pause following, forget a selected website and its associated continuity memory, or use Delete all local data in options to remove mappings, followed sites, graph history, public-source jobs/candidate evidence, discovery-service settings/session tokens, activity and the catalog cache. Clearing cancels local work and attempts to cancel outstanding configured-service jobs when possible; it cannot undo already transmitted queries or guarantee a provider refund or deletion from independently operated servers. Consult the service/provider policies for their retention and deletion mechanisms. Public catalog rollback and alias-reservation security metadata is retained: deleting settings, expiry or withdrawal must not turn a formerly signed source into an unverified route. This retained metadata contains public registry sequence/digest information and source origins, not private browsing paths or response bodies. The current export/import feature backs up manual mappings, not followed-source enrollment or the learned graph. Protect exported mapping files. Removing the extension normally removes its local extension storage; switching between unpacked and Store installations can create different extension IDs/storage.

Direct website requests and third parties

This extension is not network-free. Pressing Find current address or checking a followed source can send bounded requests directly from your browser to that source and its explicitly declared successors. Visiting or explicitly checking an opted-in shared mapping group instead starts at its current destination root and checks supported successors as described above. Each contacted website can see ordinary connection/request metadata, including your IP address and request timing. Those operators' own policies govern their server logs; the extension publisher does not control those logs. Per-origin access is requested before checking an origin unless you explicitly grant optional access across HTTPS websites.

Direct website/candidate probe requests omit cookies/HTTP credentials, use no referrer, remove original query/fragment data and do not execute downloaded JavaScript. Archive provider calls likewise omit cookies/referrers but use the constrained public-source query parameters described above; an optional service request intentionally includes its service-only access token. Redirects are requested in manual mode so a next target can be inspected before a separate permitted request. Public-path redirect targets may be visited transiently while resolving the chain; only origin links are retained. Browser-side hostname/literal checks do not independently pin DNS answers or connected IPs, so they are not a guarantee of isolated public-only egress.

The default build has no configured remote registry endpoint, publisher analytics, advertising or general browsing-history upload. No account, backend or paid search key is required for direct browser continuity or keyless archive investigation. An optional search service can require its own individual access token/account, as disclosed by its operator. When you choose to open a resulting website, or enable source/shared-destination following and navigate to a selected source, ordinary browser navigation is subject to your browser's normal site/session behavior. Web Switcher does not migrate cookies or logged-in sessions across domains.

A separately configured registry build can also download signed data from its fixed HTTPS endpoint; that server sees connection metadata. Before distributing such a build, its operator must publish matching endpoint, server-retention and contact disclosures. This browser-extension policy is not a complete policy for a separately operated server service.

Permissions and control

Storage saves local settings and bounded continuity memory. Declarative network request rules intercept eligible navigation only for selected/granted followed sources or mappings. Active-tab access supports the user-invoked popup. Alarms perform maintenance. The webRequest permission reads response headers/error events only for correlated active website/archive/service requests initiated by this extension; unrelated request events are ignored, not recorded as browsing history. The webNavigation permission handles committed top-level metadata for the extension's own packaged gates as described above; it does not query the browser history database or collect unrelated website URLs.

By default, selected-source and next-origin permissions are requested at a user gesture. Starting public-source investigation separately requests the fixed archive provider origins or the configured service origin. Candidate access is requested before checking it; those grants persist according to browser settings until you revoke them. An unchecked-by-default option lets you explicitly grant access across HTTPS websites so your chosen continuity chains can continue without a permission prompt at each new origin. That grant does not enroll every website, enable general browsing-history collection or change source-declared observations into verified ownership. You can deny/revoke access, pause individual/global switching, forget sites and uninstall in Chrome settings.

Use of data and trust limits

The default publisher does not receive your locally stored mappings, followed-site list or continuity graph and does not sell them, use them for advertising, or upload them for unrelated purposes. Direct probes necessarily reveal the contacted host to that website's operator, and explicitly requested public-source lookups disclose the selected hostname to the chosen archive/service recipients as described above. Source-declared moves are observations, not independent registry review, owner verification or a guarantee that destination content is safe. Public-source discovery can help a dead source without local history, but no available public trace or adequate continuity evidence may exist. Such a source can remain unresolved.

Contact and changes

Use the developer contact shown on the Chrome Web Store listing for private questions. Before a listing exists, use the repository owner's published contact route on GitHub. General issues can be reported in the repository issue tracker; do not post private browsing URLs, passwords or personal evidence publicly. Material changes to the distributed extension's data practices must be reflected in this policy and its Store disclosures.
